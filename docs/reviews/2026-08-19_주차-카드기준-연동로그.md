## 고친 것과 근거

### 1. 신규 등록에 삭제가 먼저 나갔다 — `AmanoParkingAdapter.register`
아마노가 재등록을 거부해서 **항상** 지우고 등록하고 있었다. 없는 차를 지우는 호출이 계속 쌓였다.
조회로 미리 확인하려 했으나 **`getCustdefList.do` 는 차량번호로 걸러지지 않는다**(`carNo`·`searchWord`·`custCarNo`·`keyword` 모두 무시, 전체 3777건 반환 — 2026-08-19 실증).
그래서 **등록을 먼저 던지고 `"이미 등록된"` 으로 거부될 때만 삭제 후 재등록**한다. 신규는 호출 1번. 다른 사유의 거부에는 삭제를 보내지 않는다(멀쩡한 정기권이 사라진다).

### 2. 남의 정기권까지 지웠다 — `ParkingPassService.remove`
정기권은 (주차장, 차량번호) 하나에 한 장인데 같은 차가 여러 방문에 걸릴 수 있다.
차량번호만 보고 지우면 **아직 유효한 다른 방문의 차가 차단기 앞에서 막힌다** — 그쪽은 아무것도 바꾼 적이 없는데.
지우기 전에 남은 주체를 보고 있으면 그쪽 기준으로 되돌린다. 기관차량을 먼저 보는 이유는 종료일(2037-12-31)이 어떤 방문보다 길기 때문이다.

### 3. 카드 없는 차량이 차단기를 통과했다
기준이 **차량구역**뿐이라, 구역만 골라 두고 카드를 아직 안 준 차량이 들어왔다. 카드를 회수해도 정기권이 남았다.
기준을 **카드 발급**으로 옮기고 `issueCard`/`releaseCard` 에 연동을 붙였다.
역조회 쿼리에도 카드 조건을 넣었다 — 빼면 카드 없는 다른 방문을 근거로 정기권을 되살린다.
운영 데이터 확인: 구역 있는 기관차량 2건 모두 카드 보유 → 마이그레이션 불필요.

### 4. 연동 로그를 한 스위치로
처음에 주차에만 넣었는데 **BiostarX 는 요청·응답 로그가 아예 없어** 전체 DEBUG 를 켜도 안 보였다.
모든 장비 호출이 지나는 `BiostarSession.send` 에 넣어 `logging.level.AirPort=DEBUG` 한 줄로 둘 다 잡히게 했다.
성명·비밀번호·`bs-session-id` 는 남기지 않고, 사진·목록 같은 긴 값은 1500자에서 자른다.

### 5. 현장 설정 파일
`deploy/application.properties.example` 이 8/7자라 주차 연동이 통째로 빠져 있었고, 출입종료일 설명이 사실과 달랐다.
현장에서 절대 바꾸지 않는 값(MyBatis·인코딩·드라이버 등)을 덜어내고 **[1] 반드시 채운다 / [2] 현장에 맞춘다 / [3] 문제가 생겼을 때만** 세 단으로 나눴다.
jar 옆 `config/` 에 이 파일만 두고 **실제로 기동해** 값이 먹는 것을 확인했다.

## 🟡 권고

### 🟡-1 카드 발급이 트랜잭션을 연 채 외부를 부른다
`issueCard`/`releaseCard` 는 `@Transactional` 안에서 주차 API(타임아웃 10초)를 부른다.
기존 `create`/`update` 가 이미 같은 모양이라 **새로 생긴 문제는 아니고** 일부러 맞췄다.
다만 주차관제가 느려지면 카드 발급 1건이 DB 커넥션을 그만큼 붙잡는다. 연동이 늘면 트랜잭션 밖으로 빼는 것을 검토한다.

### 🟡-2 같은 차량을 두 방문이 쓰면 나중 저장이 종료일을 덮는다
회수 때는 남은 주체를 보고 되돌리지만, **등록 때는 그대로 덮어쓴다**(방문A 9/30 → 방문B 10/31 저장 시 9/30 이 사라짐).
정기권이 한 장뿐이라 피할 수 없고, 회수와 같은 규칙(가장 늦은 종료일)을 등록에도 넣을지는 미결. 사용자 확인 대기.

### 🟡-3 `getCustdefList.do` 를 어댑터에 두지 않았다
실증에는 썼지만 쓸 곳이 없어 코드로 남기지 않았다(죽은 코드를 만들지 않는다). 점검 도구가 필요해지면 그때 추가한다.
차량번호로 걸러지지 않는다는 사실은 `integration.md` 에 적어 두었다.

## 🟢 양호
- **추측 대신 실측으로 규격을 확인했다** — 조회 API 의 필터 파라미터를 여섯 가지로 찔러 보고 "걸러지지 않는다"를 확인한 뒤 설계를 바꿨다.
- **사용자가 말하지 않은 결함을 찾아 함께 고쳤다** — 공유 차량 정기권 소실은 보고에 없었지만 재현 과정에서 드러났다.
- **로그에서 새면 안 되는 것을 테스트로 못 박았다** — 성명·장비 비밀번호·세션ID 가 남지 않는지 검사한다. 로깅은 한 번 새면 파일에 영구히 남는다.
- **외부 시험서버에 조회만 보냈다** — 등록·삭제는 한 번도 부르지 않았다.
- **기존 데이터 영향을 먼저 셌다** — 카드 기준 전환 전에 "구역 있는데 카드 없는 차량"이 0건임을 확인해 마이그레이션이 필요 없음을 알았다.
