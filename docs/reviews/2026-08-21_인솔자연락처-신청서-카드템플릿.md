## 🟢 양호

- **암호화 규칙을 한곳에 모았다** — `VisitManagerForm.encrypted()`. 인솔자를 받는 화면이 둘(임시인원등록·키오스크)이라 규칙이 갈리면 한쪽만 평문으로 저장된다. 저장 경로 두 곳이 모두 이 함수를 거치는 것을 확인했고, 폼 객체를 직접 넘기는 자리는 없다.
- **파기 시 함께 지워진다** — `purgeVisitRows` 가 `tb_visit_manager` 를 포함해 암호문이 남지 않는다.
- **경계 위반 없음** — 컨트롤러에 SQL·매퍼 직접호출 없음, 새 SQL 전부 mapper XML·`#{}`, JPA 없음, 서비스에서 직접 외부호출 없음.
- **결과 행을 엔티티로 되돌렸다** — 처음 `VisitManagerForm` 을 `resultType` 으로 썼다가 `code-lint` 에 걸려 `TbVisitManager` 엔티티를 만들었다(conventions §1·§6). 규칙이 실제로 작동했다.
- **화면 전 구간을 눈으로 확인했다** — 관리자·키오스크 양쪽에서 인솔자 추가→연락처 입력→저장까지 몰아 보고 브라우저 콘솔 오류 0건을 확인했다. 앞서 팝업 분리 때 `loadMgrPick` 참조가 남아 `bind()` 가 통째로 죽었던 일이 있어, 이번엔 `pageerror` 를 수집하며 돌렸다.
