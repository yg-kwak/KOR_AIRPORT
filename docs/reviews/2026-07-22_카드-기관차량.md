## 🔴 차단

### 🔴-1 실물 카드 1장이 인원과 차량에 동시 발급될 수 있다
`tb_card` 는 `person_id`(인원 카드)와 `car_id`(차량 카드)를 **배타적으로** 쓰기로 했는데, 인원 쪽 경로가 `car_id` 를 전혀 보지 않는다.

- [TbCardMapper.xml:108](../../src/main/resources/mapper/TbCardMapper.xml:108) `selectUnassigned` 가 `person_id IS NULL` 만 검사 → **차량에 발급된 카드가 정규인원등록의 '할당하기' 팝업에 미할당으로 노출**된다.
- [CardService.java:174](../../src/main/java/AirPort/service/CardService.java:174) `register()` 가 `known.getPersonId() != null` 만 거부 → 차량 카드를 그대로 재사용해 준다.
- [TbCardMapper.xml:64](../../src/main/resources/mapper/TbCardMapper.xml:64) 인원 흐름의 `update` 가 `person_id` 만 세팅하고 `car_id` 를 비우지 않는다 → 두 컬럼이 동시에 채워진다.

반대 방향인 [CompanyCarService.java:194](../../src/main/java/AirPort/service/CompanyCarService.java:194) `issueCard()` 는 `personId`·`carId` 를 **둘 다** 검사해 막는다. 즉 한쪽만 뚫려 있는 비대칭이다.

출입통제 시스템에서 한 장의 카드가 사람과 차량에 동시에 귀속되면 출입 이력의 주체가 모호해진다.

**수정 방향**: ① `selectUnassigned` 에 `AND car_id IS NULL` 추가 ② `register()` 에서 `carId != null` 도 거부 ③ 인원 흐름 `update` 에 `car_id = NULL` 추가(인원 카드로 전환됨을 명시). 나아가 스키마에 배타성 제약(`CHECK (person_id IS NULL OR car_id IS NULL)`)을 두면 코드 실수와 무관하게 강제된다.

### 🔴-2 차량에 발급된 카드를 카드등록관리에서 삭제할 수 있다
- [CardService.java:111](../../src/main/java/AirPort/service/CardService.java:111) `deleteCard()` 가 `existing.getPersonId() != null` 만 검사한다. `car_id` 가 있는 카드는 그대로 소프트 삭제된다.
- 삭제되면 `selectByCar`(`del_yn='N'` 필터) 결과에서 빠지므로 **차량의 카드가 조용히 사라지고**, "발급된 카드가 있는 차량은 삭제 불가"([CompanyCarService.java:170](../../src/main/java/AirPort/service/CompanyCarService.java:170)) 통제까지 함께 우회된다.
- 같은 이유로 [TbCardMapper.xml:34](../../src/main/resources/mapper/TbCardMapper.xml:34) 의 할당여부 필터도 차량 카드를 '미할당'으로 표시한다.

**수정 방향**: 삭제 차단 조건과 할당여부 판정을 `person_id IS NOT NULL OR car_id IS NOT NULL` 로 통일.
