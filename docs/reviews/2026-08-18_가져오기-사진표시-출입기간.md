## 🟢 양호

- **단방향이 유지됐다** — 가져오기를 크게 고쳤는데도 장비에 쓰는 경로는 생기지 않았다. `BiostarImportAdapter` 는 여전히 읽기 전용이고, 반영은 전부 우리 DB 다.
- **우리 전용 컬럼을 지키는 별도 UPDATE** — `updateFromBiostar` 를 새로 판 판단이 옳다. 기존 `update` 를 재사용했으면 생년월일·신원조회·보안교육·인원상태가 가져오기 때문에 통째로 비워졌다.
- **미리보기와 실행이 같은 코드를 탄다**(`dryRun`) — 덮어쓰기 기능에서 "미리보기엔 없던 일"이 생기지 않는다.
- **실측으로 두 버그를 잡고 회귀 테스트를 붙였다** — ① 유효기간을 `varchar(16)` 으로 읽어 초가 없는데 장비는 초까지 줘서 매번 '갱신'으로 집계되던 것, ② 카드·출입권한만 바뀐 사람이 어느 집계에도 안 잡히던 구멍. 특히 ①은 픽스처를 실제 조회 형식으로 바꿔 **되돌리면 테스트가 깨지는 것까지 확인**했다.
- **권한 검사가 빠짐없다** — 신규 공개 메서드 전부 `requireRead`/`requireCreate` 를 먼저 부른다.
- **상한과 기본값을 분리**하고 양쪽(서버·화면)이 같은 설정을 내려받는다. 기본값이 상한을 넘게 설정되면 상한으로 눌러 두는 방어까지 있다.
- **화면 판단 근거를 서버가 준다** — 실시간 이벤트의 `faceUser`. 인원 구분(PT01)은 DB 사정이라 화면이 알 일이 아니라는 기존 방침과 같다.

## 🟢 누적 상태에서 잘 지켜진 것
- **외부 연동이 전부 어댑터 뒤에 있다** — BiostarX(사용자·카드·이벤트·가져오기), 아마노(정기권·입출차 수신), 카드프린트. `service`/`controller` 에 HTTP 호출이 하나도 없다.
- **실패 정책이 일관된 기준으로 갈린다** — "그 기능이 없으면 출입이 뚫리는가". 뚫리면 롤백(BiostarX 동기화·카드 차단), 막히기만 하면 경고+저장 유지(주차 정기권·카드 차단 해제). conventions.md 에 규칙으로 등록돼 있다.
- **되돌릴 수 없는 동작에 미리보기가 있다** — 가져오기(덮어쓰기)·정기 파기 모두 dry-run 이 실행과 같은 코드를 탄다.
- **실측으로 잡은 버그마다 회귀 테스트** — 아마노 중복 등록 거부, 유효기간 분 단위 비교, 집계 구멍, 종별 없는 구역 우선 선택. 되돌리면 실제로 깨지는 것까지 확인한 것이 둘.
- **린트가 실제로 일을 한다** — 이번 세션에서 `schema-drift` 가 문서 누락을, `code-lint` 가 JS 크기 초과를 잡았다.
