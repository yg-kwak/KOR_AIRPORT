## 🔴 차단

### 🔴-1 커밋된 응답에서 난 진짜 오류가 ERROR 로 남지 않는다

[GlobalExceptionHandler.java:54](../../src/main/java/AirPort/common/exception/GlobalExceptionHandler.java#L54)

```java
if (isClientGone(e) || response.isCommitted()) {
  log.info("클라이언트가 연결을 끊었습니다 — 응답을 쓰지 않는다: {}", rootMessage(e));
  return null;
}
```

두 조건을 한 갈래로 묶은 것이 문제다. **응답이 이미 나갔다는 것과 클라이언트가 끊었다는 것은 다른 사실**인데
같은 처리를 받는다.

실제로 밟히는 경로: `ExcelUtil.download` 는 `HttpServletResponse` 에 직접 쓴다. 스트림 도중에 예외가 나면
응답은 이미 커밋 상태다 → **ERROR 스택 대신 INFO 한 줄**, 그것도 "클라이언트가 연결을 끊었습니다"라는
**사실과 다른 문구**로 남는다. 엑셀 다운로드는 감사추적·인원·기관 등 여러 화면이 쓴다.

이 화면 작업이 내내 경계해 온 "죽은 줄 모르는 것"을 전역 핸들러에 들여놓은 셈이다.

**수정 방향**: 두 갈래로 나눈다.
- `isClientGone(e)` → INFO 한 줄, 본문 없음 (지금 의도한 그대로)
- `response.isCommitted()` (끊김이 아님) → **`log.error` 로 스택을 남기고** 본문만 생략

## 🟢 양호

- **비밀값**: 하드코딩 없음. 접속정보는 `tb_system` 에서 읽어 ARIA 복호화, 로그·화면 어디에도 안 실린다.
  실패 payload 로깅도 기존 마스킹 경로를 그대로 탄다.
- **계층 경계**: `MonitorController` 는 권한 확인·위임만 한다. SQL·업무 판단이 없다.
  `MonitorService` 가 mapper·adapter 를 부르고, 컨트롤러는 `SseEmitter` 를 돌려줄 뿐이다.
- **외부 격리**: BiostarX 접촉은 전부 `adapter`(`BiostarEventSocket`·`BiostarEventAdapter`·`BiostarAdapter`).
  서비스가 HTTP·WebSocket 을 직접 다루지 않는다.
- **MyBatis 규약**: 새 조회 2건 모두 XML + `#{}`. 문자열 연결도 `${}` 도 없다. JPA 도입 없음.
  `top` 이 MSSQL 예약어라 `rootg` 로 바꾼 것도 정확하다.
- **menu_id 비하드코딩**: `CurrentMenu` 로 받아 권한·감사에 쓴다. `@RequestMapping` == `tb_menu.menu_url`(lint 통과).
- **잠금 순서**: `viewerLock → 소켓 lock` 한 방향뿐이다. 소켓이 상태를 알릴 때는 **자기 lock 을 놓은 뒤**
  `notifyStatus()` 를 부르므로 역방향 획득이 없다 — 데드락 경로가 없다.
- **감사 폭주 방지**: 재연결이 3초마다 오는 상황에서도 구독 감사는 10분에 1회. 감사추적이 덮이지 않는다.
- **테스트**: 표기표(통과 3종·거부 2종·이름 폴백)·소켓 주소·실제 MESSAGE 파싱·소켓 수명·클라이언트 끊김까지
  회귀가 잡힌다. 특히 "실패하면 `isReady()` 가 거짓이고 사유가 남는다"를 고정한 것이 이 기능의 핵심 불변식이다.
