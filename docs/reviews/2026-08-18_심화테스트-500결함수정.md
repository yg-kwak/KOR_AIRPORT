## 🔴 차단
없음.

- **계층**: 새 클래스 3개(`SearchDates`·`Texts`·`JsonConfig`)는 모두 검증·설정이며 SQL 을 갖지 않는다. 컨트롤러에 로직이 새지 않았다.
- **MyBatis**: SQL 변경 없음. `PageParam.getSize()` 보정은 Java 쪽이고 mapper 는 그대로 `#{size}` 를 받는다.
- **비밀값·JPA·adapter 우회**: 없음(diff 스캔 확인).
- **암호화**: ARIA 경로에 손대지 않았다. `ariaDecrypt` 의 `trim()` 은 그대로 두고 **입력 쪽을 맞췄다**.

## 고친 것과 근거

### 1. 목록 파라미터 보정 — `PageParam`
`size` 가 검증 없이 `FETCH NEXT ? ROWS` 로 내려가 `size=0`·음수에서 SQL 오류(10744)로 500 이 났다.
**공유 클래스라 목록 화면 전부가 같이** 500 이었다(인원·기관·카드·차량·사용자 실측 확인).
1..1000 으로 죄고, `getOffset()` 은 long 으로 곱해 잘랐다(오버플로 시 음수 OFFSET 방지).
엑셀은 `selectListAll`(OFFSET/FETCH 없음)이라 상한과 무관함을 mapper 로 확인했다.

### 2. 바인딩 실패 → 400 — `GlobalExceptionHandler`
`?size=xyz`·`?page=abc` 가 500 이었다. `BindException`·`MethodArgumentTypeMismatchException` 을 400 으로 받는다.

### 3. 기간 형식 → 400 — `SearchDates`
`startDate=2026-13-45` 가 `CAST(? AS datetime2)` 까지 내려가 SQL 오류(241)로 500 이 났다.
기간을 쓰는 화면이 둘(감사추적·주차 조회)이라 한곳에 모았다.

### 4. 길이 초과 → 400 — `Texts` + 절단 오류 그물
두 겹이다. 자주 쓰는 항목은 서비스에서 먼저 잡아 **어느 항목이 몇 자 넘었는지** 알리고,
나머지 수십 개 컬럼은 핸들러가 MSSQL 절단 오류(8152/2628)를 400 으로 받는다.
컬럼을 사람이 하나씩 적어 두면 반드시 빠지기 때문에 그물을 함께 둔다.

### 5. 입력 trim 일관화 — `JsonConfig`
`ariaDecrypt` 가 블록 패딩을 벗기며 `trim()` 을 걸어 **암호화 컬럼만 앞뒤 공백이 사라지고 평문 컬럼은 남았다**.
같은 화면에서 항목마다 동작이 달랐다. 서비스마다 `trim()` 을 흩으면 새 항목에서 빠지므로 **들어오는 문 하나**에서 통일했다.

## 🟡 권고

### 🟡-1 전역 String 역직렬화기의 사정권이 넓다
`JsonConfig` 는 요청 JSON 의 **모든** 문자열을 trim 한다. 지금은 그게 옳지만(성명·기관명·비고 어디서도 앞뒤 공백이 의미를 갖지 않는다),
앞뒤 공백이 데이터인 항목이 생기면 조용히 잘린다. 그런 항목이 생기면 그 필드만 전용 역직렬화기로 예외 처리해야 한다.
현재 BASE64 사진·얼굴 템플릿은 앞뒤 공백이 없어 영향 없음을 확인했다.

### 🟡-2 `MAX_SIZE=1000` 은 근거가 약하다
화면이 요구하는 최대 페이지 크기를 확인한 값이 아니라 "충분히 크고 오버플로를 막는" 값이다.
목록 UI 가 1000건 이상을 한 페이지에 요구하게 되면 여기서 조용히 잘린다.

- **수정 후 재실측했다** — 네 결함 모두 응답 코드와 메시지를 직접 찍어 확인했고, 심화 234/0 · 스모크 185/0 으로 회귀가 없음을 봤다.
