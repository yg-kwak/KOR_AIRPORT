## 🔴 차단

### 🔴-1 장기출입등록 화면의 [신청서 출력] 버튼이 동작하지 않는다
[visitor.html:213](../../src/main/resources/templates/web/visitor/visitor.html) · [permit-print.js:130](../../src/main/resources/static/js/web/visitor/permit-print.js) — 커밋 `d361d9a`

임시인원등록과 장기출입등록은 **같은 화면(`web/visitor/visitor`)을 공유**한다
([LongTermController:83](../../src/main/java/AirPort/controller/LongTermController.java), [VisitController:82](../../src/main/java/AirPort/controller/VisitController.java)).
버튼과 `permit-print.js` 를 그 템플릿에 넣었으므로 **장기 화면에도 버튼이 뜬다.**
그런데 신청서 엔드포인트는 `VisitController` 에만 있다.

```
GET /visitor/visitor/permit?visitNo=17   → 200
GET /visitor/longterm/permit?visitNo=17  → 500   ← 실제 호출로 확인
```

장기·상주·순찰·대여 방문을 열고 버튼을 누르면 오류만 난다.

→ 수정 방향 두 가지 중 택일.
   **(가)** 장기에도 신청서가 필요하면 `LongTermController` 에 같은 엔드포인트를 추가한다.
   다만 양식 제목이 "보호구역**1일** 임시출입허가" 라 장기에 그대로 쓸 수 있는지 발주처 확인이 필요하다.
   **(나)** 임시 전용이면 `VISIT_CFG.fixedType` 로 화면을 구분해 임시에서만 버튼을 노출한다.

## 🟡 권고

### 🟡-1 `VisitPermitService` 에 테스트가 없다
[VisitPermitService.java](../../src/main/java/AirPort/service/VisitPermitService.java)

단순 조회가 아니라 분기가 있다 — 구역명에서 번호 뽑기(`areaNos`, 번호 없는 이름은 원문 유지),

지금은 실제 API 호출과 눈 대조로만 확인했다.

→ 위 세 분기에 단위 테스트를 붙인다.

### 🟡-2 실패 payload 로그가 진단에 필요한 이름까지 가린다
[BiostarSession.java](../../src/main/java/AirPort/adapter/BiostarSession.java) — 커밋 `f6c4ab4`

`"name"` 키를 전부 가려 **`card_type.name` 도 `***`** 이 된다. 실제 현장 로그에서 확인됐다.
카드 타입명은 개인정보가 아니고 원인 파악에 쓰인다.

```
"card_type":{"id":"0","name":"***","type":"1"}
```

→ 문자열 정규식 대신 JSON 으로 파싱해 `User.name`·`User.phone`·`User.photo` 만 가린다.

### 🟡-3 시스템 사건 유형명이 두 곳에 흩어져 있다
[TbSystemLogMapper.xml](../../src/main/resources/mapper/TbSystemLogMapper.xml) · [AuditService.java](../../src/main/java/AirPort/service/AuditService.java)

`STARTUP`·`SHUTDOWN`·`PURGE` 는 `tb_common(AT)` 에 두지 않기로 했다(유형 목록에 섞이면 고를 곳이 두 군데가 된다).
그래서 화면에 보이는 이름(`시스템 시작` 등)을 mapper 의 `CASE` 가 붙인다 — **코드값은 Java 상수, 이름은 mapper** 로 나뉘었다.
유형이 늘면 두 곳을 같이 고쳐야 한다.

→ 지금은 3개뿐이라 감수할 만하다. 늘어나면 한쪽으로 모은다.

### 🟡-4 정기 파기가 켜졌는지 확인할 방법이 이력뿐이다
[VisitPurgeService.java](../../src/main/java/AirPort/service/VisitPurgeService.java)

기본이 미리보기(`dry-run=true`)라 현장에서 **켜는 것을 잊기 쉽다.** 지금은 다음 실행의 감사 이력 문구
("(미리보기 — 실제로 지우지 않음)")를 봐야 알 수 있다.

→ 기동 시 현재 모드·보존기간·주기를 로그 한 줄로 남기면 재시작 직후 바로 확인된다.

### 🟡-5 신청서가 생년월일·연락처를 브라우저로 내려보낸다
[VisitPermitService.java:88](../../src/main/java/AirPort/service/VisitPermitService.java)

양식에 필요한 값이고 `requireRead` 권한과 `DOWNLOAD` 감사가 걸려 있어 추적은 된다.
수정 화면 상세에서도 이미 내려가는 값이라 **새로운 노출은 아니다.**

→ 인쇄물에 생년월일·연락처가 남는 것이 발주처 개인정보 처리방침과 맞는지 한 번 확인한다.

## 🟢 양호

- **불변식 무위반** — 이번 변경의 SQL 은 전부 mapper XML, `${}` 0건, 인라인 SQL·JPA 0건,
  service 계층의 직접 HTTP 호출 0건(BiostarX 는 전부 adapter 경유).
- **파기의 안전장치가 실제로 걸린다** — 장비 먼저 삭제(실패 시 DB 미변경), 인솔자(정규인원) 제외,
  기관차량 제외, 다른 방문에 있는 인원 제외, 1회 상한, 기본 미리보기. 5건의 테스트로 고정했다.
- **0건이어도 실행 이력을 남긴다** — 배치가 멈춘 것과 지울 게 없는 것을 구분할 수 있다.
- **개인정보 취급 일관** — 성명·생년월일·연락처는 ARIA 복호화 경로로만 다루고 키 하드코딩 없음.
  실패 payload 로그도 가려서 남기며, 로그인 본문은 그 경로를 타지 않아 비밀번호가 실릴 수 없다.
- **동기화 실패가 상태로 새지 않는다** — 장비에 못 올리면 '신청' 으로 되돌려, 카드가 열리지 않는데
  처리된 것처럼 보이는 상황을 막는다.
- **회귀를 규칙으로 막았다** — 게터 누락(검색 조건이 조용히 무시되던 버그)을 ArchUnit 규칙으로 차단하고
  게터를 지워 실제로 실패하는 것까지 확인했다.
- **테스트 110건 통과** — 파기 5 · 기동/종료 3 · payload 마스킹 4 · 동기화 실패 2 등 신규 로직마다 추가.
